# Архитектура

## Слои

```
                     +---------------------------+
   zeliboba.exe      |  src/debug/cli.cpp        |  консольный фронтенд
   zeliboba_ui.exe   |  src/ui/*                 |  SDL3-фронтенд
                     +------------+--------------+
                                  | команды / представления
                     +------------v--------------+
                     |  src/debug/debugger.cpp   |  отладчик (один на оба фронтенда)
                     +------------+--------------+
                                  |
                     +------------v--------------+
                     |  src/machine/vita.cpp     |  машина: шины, ядра, планировщик
                     |  src/machine/bootchain.cpp|  цепочка загрузки
                     |  src/event/*              |  события ETW-стиля (сессия машины)
                     +---+----------+-----------+--+
                         |          |           |
        +----------------v--+  +----v-------+  +v-----------------+
        | src/hw/cmep       |  | src/hw/soc |  | src/hw/syscon    |
        | keyring, bigmac,  |  | GIC, UART, |  | SFR, SC-канал,   |
        | bignum, mailbox,  |  | timers,    |  | eMMC-хост,       |
        | strap, GPIO, SC   |  | SDIF, DMA, |  | питание, RTC     |
        |                   |  | display    |  |                  |
        +--------+----------+  +-----+------+  +--------+---------+
                 |                   |                  |
        +--------v-------------------v------------------v---------+
        |  src/bus : Bus (RAM + MMIO + page table + TraceLog)      |
        +--------+-------------------+------------------+---------+
                 |                   |                  |
        +--------v------+   +--------v------+   +-------v---------+
        | src/cpu/mep   |   | src/cpu/arm   |   | src/cpu/rl78    |
        | MeP-c5 (CMeP) |   | Cortex-A9 x4  |   | RL78 (Ernie)    |
        +---------------+   +---------------+   +-----------------+
```

Kermit — это **четырёхъядерный** Cortex-A9 MPCore: `Vita` держит четыре `ArmCore`
(`arm_cores_`), у каждого своё CP15/MMU-состояние и свой `core_id_`, который
отдаётся через `MPIDR` (`c0,c0,5`). Ядра идут синхронно по одному «срезу»
(`run_slice`), а `kernel_boot_loader` различает их именно по `MPIDR` и сводит в
своём барьере. В отладчике ядро выбирается как `core arm0` … `core arm3`
(`core` без аргументов печатает весь кластер), `arm()`/`Arch::Arm` — это ядро 0.

Загрузчики контейнеров (`src/loader/`) не знают о ядрах: они получают `Bus&`,
раскладывают сегменты и возвращают точку входа.

## Шина

`zlb::Bus` владеет:

* **регионами RAM** (`MemRegion`) — либо собственным буфером, либо алиасом чужого
  (`external`), что даёт разделяемую память между ядрами;
* **MMIO-устройствами** (`Device`) — при пересечении окон выигрывает устройство с
  меньшим окном, поэтому подустройство может перекрыть большое;
* **таблицей страниц 4 КиБ** — быстрый путь для RAM (`memcpy`), медленный путь для
  MMIO и частично покрытых страниц;
* **`TraceLog`** — кольцевой буфер обращений (по умолчанию 262 144 записи, то есть
  256 Ки; RAM пишется только при `trace_ram = true`, MMIO — всегда).

Каждое ядро обязано перед обращением выставить `bus.context.core` и
`bus.context.pc` — иначе трейс и точки наблюдения теряют смысл.

## Ядра

`zlb::Cpu` (`src/cpu/cpu.h`) — общий интерфейс: `reset()`, `reset(entry)`,
`prepare_reset_context()`, `step()`, `disassemble()`, `registers()`,
`set_register()/get_register()`, `set_irq()`, `interrupt_pending()`, `tick()`.

`prepare_reset_context(a0..a3)` — архитектурно-зависимое окружение сброса:
для ARM это `r0..r3`, для MeP — `$0` (будущий `$sp`), для RL78 не используется.

Ядра создаются фабриками в `src/cpu/factory.h`, поэтому машина не зависит от
внутренностей конкретного ядра.

## Машина

`zlb::Vita` владеет тремя шинами, четырьмя ядрами ARM (`arm_cores_`), ядром CMeP,
блоками железа и картой eMMC; ядро RL78 принадлежит `ErnieBlock` (у него свой
`syscon_bus`). Планировщик простой и детерминированный: `run_slice()` даёт каждому
ядру фиксированный бюджет инструкций (`CoreBudget`), затем вызывает
`poll_boot_chain()`. Детерминизм важен для воспроизводимости отладки.

Время эмулируется по тактовой частоте Cortex-A9 (333 МГц), поэтому
`emulated_seconds()` монотонно и не зависит от хоста.

## Цепочка загрузки

`src/machine/bootchain.cpp` — конечный автомат из `BootStage`. Он же содержит
C++-модель шага «ARM boot ROM» (нет дампа), о которой подробно написано в
`docs/BOOT.md`. Любую стадию можно включить вручную командой `stage`, что
позволяет отлаживать ядро, не доводя до конца предыдущие стадии.

## Модельные подстановки

Цепочка загрузки идёт на подстановках: там, где нужного кода или данных в дампах
нет (ARM boot ROM, сервис первого загрузчика `0x5FF00`, карта памяти, которую KBL
наследует от предыдущей ступени, структура устройства хранения NSKBL), модель
подставляет своё поведение. Все подстановки собраны в одном месте
(`src/machine/bootchain.cpp`, `src/hw/cmep/bigmac.cpp`) и отключаются переменной
`ZLB_NO_SUBSTITUTION=1`; их список с точными адресами — `docs/STATUS.md` §4.
Подстановка, которая адресует немапированную память, теперь отвергается с
предупреждением (тест `second_loader_substitutions_stay_inside_the_staged_image`).

Отсюда важное следствие для детерминизма: прогон детерминирован **при
фиксированном наборе переменных среды** (`ZLB_*`), потому что часть из них меняет
не только диагностику, но и поведение модели — например сторож сна кластера в
`run_slice()`. Воспроизводимость измерений требует указывать эти переменные вместе
с результатом.

## Отладчик

`zlb::Debugger` не владеет машиной, а ссылается на неё. Команды — текстовые,
поэтому GUI и консоль используют один и тот же код, а сценарии отладки
воспроизводимы. Точки наблюдения работают поверх `TraceLog`.

`src/event/` — независимый слой наблюдаемости: провайдеры с манифестами, события
с уровнями/ключевыми словами/задачами и активностями Begin/End, кольцевой лог и
запросы (фильтры, сводка, гистограмма, CSV). `Vita` владеет сессией и делает её
активной процесс-глобально (`zlb::events()`), поэтому шина, устройства и ядра
эмитят события, не зная о машине. Отладчик владеет фильтром вида, который
использует и панель Events. Подробности — `docs/EVENTS.md`.

## Правила разработки

См. `docs/DEVELOPMENT.md`: C++20, `namespace zlb`, никаких зависимостей кроме
SDL3, никаких исключений через публичный API, никакого недетерминизма в ядрах
(никакого wall clock и `rand` — аппаратный RNG это устройство).
