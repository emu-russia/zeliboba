# Venezia (MPE) — план второго этапа

## Что это

Venezia — второй вычислительный движок SoC: отдельное ядро **MeP** с расширением
**IVC2** (VLIW: пары инструкций за такт) и своей SPRAM. Прошивка ядра грузит в него
образ через модуль `os0/kd/vnzimg.skprx`.

## Аппаратные факты (Copetti part 1 + wiki Venezia) **[В]**

Всё в этом разделе — цитаты из внешних источников (wiki/Copetti), в модели
**не проверено**; ничего из этого пока не подтверждено ни дампом, ни кодом
прошивки в рабочей папке:

Источники: <https://www.copetti.org/writings/consoles/playstation-vita/> (section
«The new media coprocessor», memory section) и
<https://wiki.henkaku.xyz/vita/Venezia>. То, что оттуда следует для нашей модели:

| Параметр | Значение |
|---|---|
| Ядер MPE | **8** (4 «набора» MPE × по 2 ядра; в wiki: «4 sets of MPE», «8 MeP cores») |
| Ядро | Toshiba **MeP-c5** (то же семейство, что CMeP/F00D) + копроцессор **IVC2** |
| Тактовая | 266.7 МГц |
| Кэш L1 | 16 КиБ I + 16 КиБ D (2-way) на ядро |
| Локальная память | 64 КиБ (16 КиБ × 4 банка) data RAM на ядро |
| Кэш L2 | 256 КиБ, 4-way, общий на 4 MPE |
| DMA | свой DMA-контроллер на каждый MPE (перекачка data RAM) |
| Таймеры | 2 канала |
| Отладка | JTAG/ICE, общий на control-MeP и Venezia |
| CPU ID | `ldc $2,17` ($id) у восьми ядер = `0x00300500`, `0x00310500`, … `0x00370500` (номера ядер 48…55) — **по вики, в модели не проверено** |
| SPRAM | PA `0x1F840000`, размер `0x20000` («SceVeneziaSpram») |

**SPRAM на этапе загрузки.** Wiki прямо говорит: *SceVeneziaSpram используется как
временное место хранения зашифрованного `secure_kernel`*; если её обнулить,
secure_kernel не загрузится (хотя оболочка при resume покажется). В нашей модели
SPAD128K по адресу `0x1F840000` **пока не отображён вообще** — это отдельный
пункт ниже (проверить, обращается ли туда KBL: `ZLB_RTRAP=1f840000-1f860000`).

**Карта памяти с точки зрения самих MPE** (wiki, таблица Memory Map; кэш-политики
в ней — про MPE, не про ARM):

| Начало | Конец | Размер | Комментарий |
|---|---|---|---|
| `0x18000000` | `0xBFFFFFFF` | 0xA8000000 | L1/L2 cached, приватная/защищённая память |
| `0xC0000000` | `0xDFFFFFFF` | 0x20000000 | L2 cached, публичная память: зеркало, подрегионы по 128 МиБ (через Pervasive2) |
| `0xE0000000` | `0xEFFFFFFF` | 0x10000000 | uncached |
| `0xF0000000` | `0xF7FFFFFF` | 0x8000000 | зеркало, подрегионы по 32 МиБ (через Pervasive2) |

Из примера кода в wiki (`movh $0,0xf184` + запись `8` по смещению 0) **следует
(это вывод, а не цитата)**, что своя SPRAM видна ядру MPE как
`0xF1840000` = `0xF0000000 | (0x1F840000 & 0x0FFFFFFF)`,
т.е. верхний регион и есть «зеркало» физического пространства `0x1…`.

**Протокол запуска Venezia** (wiki, «Running Code»): ARM-модуль DMA-копирует
MeP-полезную нагрузку в приватную память Venezia, чистит L2 (`SceCpuForDriver … clean_l2`,
SMC `0x110`), программирует Pervasive2 (`regs[192..196]`, `regs[224..239]`,
`regs[256]`, `regs[898] = 0xFFFF0000`), пишет `spram[0] = 1` и через
`ScePervasiveForDriver 0xA7E64C6F (reset_vnz)` ждёт `spram[0] == 8`. Полезная
нагрузка, в свою очередь, читает `$id`, пишет `$id` куда-то наружу и в конце
пишет `8` в свою SPRAM — **гипотеза** (инференция из вики, дампом не
подтверждена): `spram[0]` и есть почтовый ящик «ARM → Venezia → ARM»:
`1` = старт, `8` = «код исполняется».

Полезная нагрузка начинается с шести `jmp 0x800018` (векторная таблица Venezia
по `0x80000000`+): при реализации Stage 2 это готовый тест — загрузить её и
убедиться, что после сброса исполняется `0x800018`. **Не подтверждено**: ни
`0x800018`, ни сам дамп нагрузки в рабочей папке не найдены, артефакт не указан;
проверять придётся по `vnzimg.elf`.

**Общая картина SoC (Copetti).** Kermit: 4× Cortex-A9 MPCore (до 500 МГц, 32 КиБ
L1 I/D, 2 МиБ L2 PL310, TrustZone, NEON/VFP, OCP для обмена с остальным SoC),
PowerVR SGX543MP4+, 512 МиБ LPDDR2 + 128 МиБ CDRAM (у GPU две 512-битные шины),
≈2.18 МиБ SRAM (2 МиБ Camera SRAM, SPAD32K, SPAD128K, 4 КиБ SceCompatSharedSram,
16 КиБ Scratchpad **внутри MIPS32 4k**), а также MIPS32 4k для эмуляции PSP
(к ARM напрямую не подключён — только RPC; 64 МиБ CDRAM отдано под это).

Подтверждение из материалов:

* `Vita_104_Firmware/Out/fs_dec/os0/kd/vnzimg.elf` — `SceVeneziaImage`,
  ELF32 ARM, `e_type = 0xFE04`, сегменты:
  `0x81000000` (0x84, RX), `0x81001000` (0xF6DF8 RX/RW), `0x60000000` (0x24) —
  то есть модуль ARM, внутри которого лежит образ для MeP;
* таблицы CGEN для IVC2 (VLIW-пары) и MeP-c5 (`mep-ivc2.cpu`, `mep-c5.cpu`,
  `mep-h1.cpu`, `mep-default.cpu`, `mep-ext-cop.cpu`) в рабочей папке
  **отсутствуют** — на них ссылались прежние раунды, но ни одного `*.cpu` в
  `..` нет. Для IVC2 таблицы придётся взять из binutils/GDB или
  восстановить по коду прошивки; до этого описание IVC2 остаётся планом;
* в референсной C# реализации есть профиль `MePProfile.Venezia`
  (`Sandbox.SetVenezia()`), который включает распознавание IVC2 и добавляет
  SPRAM по адресу `0x80000000`.

## Что нужно сделать

1. **Реверс `vnzimg.elf`** (ARM-модуль): найти
   * адреса MMIO-регистров Venezia (окно управления, сброс, загрузка образа,
     кольцевые буферы, почтовые ящики);
   * формат загружаемого образа (заголовок, сегменты, точка входа);
   * протокол «ARM пишет команду — Venezia отвечает» (используется для
     видеодекодирования и части медиа-конвейера).
   Инструмент: `build\bin\zdis.exe arm <file> --base 0x81001000` плюс
   `docs/DEBUGGER.md`-команды `trace find`/`watch` на работающей машине.
2. **Расширить ядро MeP до IVC2**: каркас в `src/cpu/mep` уже есть — `vliw_mode`
   (PSW бит 12), распознавание escape-опкодов IVC2/DSP (они помечаются
   `undefined`) и разбор режимов Venezia, — но **VLIW-пары не исполняются**.
   Нужны VLIW-пары (`slots`), регистры IVC2, копроцессорные операции и
   SPRAM-окно. Таблиц CGEN в рабочей папке нет (см. выше) — источник надо
   определить до начала работы.
3. **Связать с машиной**: второй экземпляр `MePCore` (`make_cpu(Arch::MeP, …)`)
   на отдельной шине + блок `hw/venezia` с регистрами из п.1, обмен через
   общую SRAM (механизм алиасов уже есть: `Bus::add_ram_alias`).
4. **Проверка**: `vnzimg` грузит образ — значит, после запуска ядра эмулятор
   должен увидеть запись образа в SPRAM и старт Venezia; точка входа образа
   обязана исполниться без `undefined instruction`.

## Что уже готово и переиспользуется

* `src/cpu/mep` — интерпретатор MeP-c5 + дизассемблер (проверен на реальном
  first_loader: 200 инструкций → `pc=0x5C018`, эталонные значения совпадают);
* `src/bus` — произвольное число шин и алиасы разделяемой памяти;
* `src/machine` — машина умеет держать несколько ядер с независимыми шинами
  (`Vita::core(Arch)`);
* `tools/zdis.cpp` — дизассемблер для ARM/MeP/RL78, основной инструмент реверса.
