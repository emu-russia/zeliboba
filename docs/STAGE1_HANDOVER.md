# Stage 1: точка передачи работ (раунд 71)

Краткая сводка состояния и всего, что нужно для следующего шага — чтобы не собирать
адреса и структуры заново. Подробности по каждому пункту — в `docs/KBL.md`
(раунды 48-70), аудит декодера — в `docs/CPU_ARM_AUDIT.md`.

## 1. Где мы находимся

* Ядро ARM теперь **корректно** декодирует: пространство умножений A32 (аудит C1),
  SDIV/UDIV, Thumb-32 MRS/MSR/SMULL/MLS, CPS/SETEND, правила флагов (A32 и T32) и
  **пространство подсказок** `NOP/YIELD/WFE/WFI/SEV` (последнее останавливало все четыре
  ядра на входе загрузчика; маска сравнения была на ниббл неверна — `0x03200F00` вместо
  `0x03200000`). Коммиты: `b6122a2`, `9599c2d`.
* С исправленным ядром прогон 20 тыс. срезов даёт **23 156 059 инструкций** (было
  2 702 334 с остановкой) и загрузчик **строит все свои объекты** (см. §3).
* Верхний барьер: загрузчик **создаёт** класс (`0x400313C8`), но **никогда не
  пользуется** его методами — трап чтений по объекту класса даёт всего два обращения,
  и оба к слову-ссылке списка, а не к ячейкам методов. Поэтому не вызывается
  `FixedHeapInit`, экземпляр кучи не создаётся, поле `[obj+0x18]` остаётся NULL, и
  цепочка «куча → кэш блоков 0x1000 → менеджер объектов `ctx+0x8C`» не запускается.

## 2. Что нужно сделать (следующий шаг)

Реализовать **подстановку «готовый реестр классов с методами»** (отключается
`ZLB_NO_SUBSTITUTION=1`, как и остальные подстановки):

* на железе реестр и классы оставляет предыдущая ступень (secure world / ARM boot
  context); загрузчик умеет только создавать классы, но не искать их — имени
  `"SceKernelFixedHeapClass"` в коде ровно одно вхождение, в самом создании;
* структура менеджера (хеш-таблица): `+0x1C` таблица, `+0x20` шаг (u16), `+0x32` число
  (u16), `+0x34` бакеты; методы класса лежат по `+0x2C`/`+0x30`;
* после подстановки проверить `tools/dbg_kbl_status.cmd`: появился ли `ctx+0x8C`,
  наполнился ли кэш блоков 0x1000 (`[pool+0x9C]` → таблица `0x52C0`, у каждого ядра
  счётчик `[+2]` и голова `[+4]`), пошла ли регистрация классов SceUID
  (`0x4002BD00`, ID `0x10001…0x1002F` шагом 2).

## 3. Карта объектов и функций KBL (всё по виртуальным адресам!)

Адреса объектов **зависят от текущих таблиц страниц** (KBL перестраивает их по ходу
загрузки, см. раунд 57) — читать только через `vpa`/`vmem`/`vpoke`, не через `mem`.

| VA | Что | Содержимое в прогоне 20 тыс. срезов |
|---|---|---|
| `0x4900` | boot context | `+0x04 = 1`, `+0x08 = 0x40000000`, `+0x0C = 0x00300000`; **`+0x8C` = менеджер объектов (0)** |
| `0x5180` | дескриптор региона | `0x40000000 0x00300000 0x00040000 0x0000C000 0x00030000` |
| `0x51C0` | раздел (partition) | `+0x08 = magic 0x4080502B`, `+0x10 = 0x00010002` (маркер свободного чанка), `+0x18/+0x1C` = регион |
| `0x5A40` | UID-entry-heap | создаётся вторым, поверх `0x5400` |
| `0x5400` | реестр класса | методы по `+0x2C`/`+0x30`, но их никто не читает |

| Адрес | Роль |
|---|---|
| `0x4002BAF8` | создание менеджера объектов (вызов из `0x4002C602`), пишет `ctx+0x8C` в `0x4002BBD6` |
| `0x400313C8` | создание класса по имени (регистр `0x5400`, имя, аргумент); пишет методы `+0x2C`/`+0x30` |
| `0x40031AC8` | `FixedHeapInit` — вызывается из `0x40031C22`, `0x40031C96`, `0x40031D40` (ни один не исполняется) |
| `0x40031654` | `FixedHeapAllocObjectWithOpt` — вызывается с `r0 = 0` (куча NULL) из `0x40031908`/`0x40031913` |
| `0x40032278` | распределитель разделов: `(pool, size, flags, &out)`; для `size == 0x1000` — только кэш, иначе нарезка |
| `0x40032356` | проверка флагов: маска `#0x33` (флаг `0x10` разрешён) |
| `0x40032768` | возврат блока 0x1000 в кэш (единственный путь наполнения кэша) |
| `0x4002BD00` | цикл регистрации классов SceUID (ID `0x10001…0x1002F`) |
| `0x4005B6BC` | строка `"SceKernelFixedHeapClass"` (одно вхождение — в создании) |

## 4. Состояние тестов и инструментов

* Самотесты: **354 прогона / 15 падений / 21 ассерт** — ровно известная база
  (8 arm, 3 cmep, 2 bigmac, 2 machine). Базовое число из цели («210 / 15») выросло
  только по числу тестов; список известных падений не изменился.
* Новые тесты ARM-агента (~1500 строк, 108 тестов) лежат в `git stash`
  («arm-agent test work in progress»): файл не компилировался (`tests/test_arm.cpp:147`,
  необъявленные `i1`/`s`/`j1`/`i2`), агент был прерван, чтобы дерево собиралось.
  Это отдельная задача: довести тесты до сборки и зелёного прогона.
* Инструменты, которые нужны на каждом шаге: `vpa <va>` / `vmem <va> [rows]` /
  `vpoke <va> <val>` (перевод через таблицы активного ядра), `faults [all]`,
  `tools/dbg_kbl_status.cmd` (снимок объектов KBL), `ZLB_WTRAP`/`ZLB_RTRAP`,
  `ZLB_ALLOC_CARVE=1` (эксперимент, по умолчанию выключен).
* Для поиска вызовов и ссылок в образе загрузчика (вопрос «кто вызывает/читает этот
  адрес») есть **рекурсивно-нисходящий** дизассемблер `tools/kbl_xref.py` (линейный
  проход по Thumb-2 декодирует мусор), а также `tools/kbl_dis.py`,
  `tools/kbl_findptr.py` и сценарии `tools/dbg_kbl_who.cmd`, `tools/dbg_kbl_steps.cmd` —
  все они перечислены в `docs/DEBUGGER.md`.
* Прогон цепочки: `verify.ps1` — все шаги загрузки проходят (кроме шага самотестов,
  который «падает» из-за 15 известных).
